# bench/ — базова линия за качеството на текста

Виж [research-plan-11-text-quality.md](../docs/research-plans/research-plan-11-text-quality.md),
Фаза 1. Целта е едно нещо: **число, с което да се сравнява**, за да не е всяка промяна в
промпт, модел или верига въпрос на усещане.

⚠ **Постовете, произведени от тези брифове, НИКОГА не се публикуват.** Брифовете са
измислени (макар и съвместими с `knowledge/identity/facts.yaml`) — имената на хора в тях не
са реални лица.

## Как се мери (безплатно, без модел)

```bash
python -m src.cli bench
```

Чете вече съществуващите папки в `posts/` и мери три неща за всеки текст: **абсолютен брой
факти** (имена + числа), **плътност** (факти на 100 думи) и **дял празни изречения**
(изречения без нито едно име и число). Показва Post I → Post II → предложение, за да е видно
коя стъпка добавя конкретност и коя маха.

Референтната лента идва от дословните постове в `knowledge/examples/good/` — не от измислена
цел, а от това, което клъстерът наистина е публикувал.

Само контролираният набор:

```bash
python -m src.cli bench --only bench-
```

## Записани базови линии

| Файл | Какво е |
|---|---|
| `baseline-pre-phase0.json` | 20-те пускания от 2026-08-10/11, **преди** хигиената на входа. Линията „както беше". |

Медиани от нея, за бърза справка:

| | думи | факти | плътност | празни изречения |
|---|---|---|---|---|
| 5 дословни поста на клъстера | 113 | **22** | 15.5 | **14.3%** |
| Post I | 96 | 10 | 10.1 | 28.6% |
| предложение | 82.5 | **9** | 10.2 | **28.6%** |

Тоест генерираният пост носи около 40% от фактите на реален пост, при двойно повече празни
изречения.

## Как се прави нова базова линия (иска реални извиквания към модела)

Пуска целия набор и записва отчет. Изпълнява се съзнателно — това са ~8 × 5 извиквания към
модела на собствения сървър.

```bash
for f in bench/briefs/*.md; do n=$(basename "$f" .md); python -m src.cli generate "posts/bench-$n" --brief "$(cat "$f")"; done
```

PowerShell:

```powershell
Get-ChildItem bench/briefs/*.md | ForEach-Object { python -m src.cli generate "posts/bench-$($_.BaseName)" --brief (Get-Content $_.FullName -Raw) }
```

После:

```bash
python -m src.cli bench --only bench- --save bench/after-phase0.json --compare bench/baseline-pre-phase0.json
```

**Задай `SEED` в `.env` преди това.** Без него две пускания със същия бриф дават различен
текст и сравнението „преди/след" мери и шума от извадката заедно с промяната.

## Какво метриката НЕ казва

Тя е прокси. Разпознаването на собствено име е евристика (главна буква не в началото на
изречение + низове в кавички + версални думи), не NER. Стойността ѝ е в **разликата** между
два текста, измерени по един и същи начин, не в абсолютното число.

Затова план 11 изисква до нея да върви и сляпа човешка оценка на същите постове: маркетинг
екипът подрежда изхода на две вериги, без да знае кой кой е. **При разминаване печелят
хората, а метриката се прекалибрира.**
